## Durable project knowledge

- **Registry digest is the only canonical identity.** Local Docker image ID, mutable
  tags, git/workflow SHA, and hosted-runner image version are explicitly NOT pins.
  Note: the local image ID equals the *config* digest (`sha256:24a926a0…`), which is
  why the pin must be the *manifest* digest (`sha256:766ce07b…`).
- **GHCR publication works with the repository-owned `GITHUB_TOKEN`** and
  `permissions: packages: write`. No new secrets/accounts/paid infra needed.
- **The package is anonymously retrievable** via the standard GHCR token flow, even
  though the REST visibility endpoints return 404 for a workflow token. Do not treat
  that 404 as a blocker.
- **The publication workflow is guarded**: a `push` may publish only while the
  committed pin is the all-zero sentinel; once a real digest is committed, a push
  runs `verify-pin` only and can never move the pin.
- **`canonical-image-pull.sh` has a recipe-drift tripwire** comparing
  `git hash-object .devcontainer/Dockerfile` against
  `CANONICAL_IMAGE_SOURCE_DOCKERFILE_BLOB`; editing the Dockerfile without a pin
  refresh fails CI closed.
- **Workflow dispatch on a feature branch only works for workflows that already
  exist on `main`.** A brand-new workflow can only run via a `push` trigger until
  merged. Also: `gh workflow run` needs the workflow *filename*
  (`ci-qemu-lane.yml`), not its `name:` (`canonical-qemu-lane`).
- **Observed failure motivating the change:** nightly run 34572559147 on
  `main @ d3eabc10` failed inside `docker build` because `apt-get install` could not
  reach `archive.ubuntu.com` — the lane never reached the QEMU smoke.

## Local environment gotcha (not a repo issue)

`git commit` in this sandbox writes the reflog but can drop the ref update when the
ref directory does not yet exist, leaving the branch apparently "unborn". Fix:
`mkdir -p .git/refs/heads/<dir>` then write the new SHA from
`.git/logs/refs/heads/<branch>` into the ref file before pushing.
