# M03 — Machine: ISA & Execution native observation activity

本目录用**同一个最小 C fixture**支撑 L03-01～L03-03。目标不是学习 C 或汇编编程，而是把“源码操作 → 编译产物 → x86-64 指令 → 寄存器/内存状态”变成可观察证据，并不断追问：**我从证据知道了什么？我又在猜什么？**

## 0. 先做 preflight

```bash
cd labs/foundations/m03
./preflight.sh
```

canonical activity 要求 `uname -m` 为 `x86_64`，并且 `cc`、`objdump`、`nm`、`gdb`、`git` 可用。脚本会记录实际版本。若不是 x86-64，或 GDB 被 hosted policy/环境阻止，请记录 `BLOCKED / NON-CANONICAL ENVIRONMENT` 或具体缺失项；不要照抄课程里的示例地址。

OQ-BP-006 仍然 OPEN：这里记录“你实际用了什么”，不宣布最终 canonical pin。

## 1. Reset → build → baseline

```bash
./reset.sh
./build.sh
./fixture
```

构建 flags：

```text
-std=c11 -Wall -Wextra -Wpedantic -g3 -O0 -fno-omit-frame-pointer -fno-inline -no-pie
```

这些 flags 是为了让**这个 activity build**易于 source mapping、call-frame 观察与重现；它们不是 C 或 x86-64 的保证。

baseline 应打印 `result=37`。

## 2. Symbol + disassembly

运行 `./inspect.sh`。它用 `nm` 确认 `main` / `helper` named symbols，生成 `disassembly.txt`（`objdump -d -S` source-aware output），并显示 bounded `helper` / call region。先预测两个 scalar arguments 是 10、20；pointee `item.value` 是 7；源码结果是 37。不要背整段汇编。

## 3. Three-point GDB trace

运行 `./capture-gdb.sh`。脚本从**当前 build 的 objdump**找到 call site 与 after-call site，再用 GDB 采集三点：before-call 的 `rip/rsp/rbp`、`rdi/rsi/rdx` 与 pointee；callee 的 frame、`a/b/item/item->value/local`；after-return 的 `rip/rsp/rbp/rax`。输出写到 `gdb-trace.txt`。

**实际地址由本次 build 决定；不要把它们写成 universal addresses。** System V AMD64 ABI 规定本活动用到的 argument/result roles；而“这个 local 恰好在某 stack offset”只属于当前 compiler/build observation。

## 4. Controlled failure

`failure.c` 保留同一个 `helper`，但传入 `item=NULL`。运行：

```bash
./build.sh
./observe-failure.sh
```

语言层先写清楚：执行 `item->value` 的无效 pointer dereference 属于 **C undefined behavior**；C 不保证 SIGSEGV。`observe-failure.sh` 只在当前 hosted Linux/build 中检查 GDB 是否实际观察到 `SIGSEGV` 并保存 `failure-gdb.txt`。signal/stop 是 evidence，不是完整 root cause、virtual-memory 机制、protection rule、Process/Isolation 语义的证明。

若本机没有 GDB，可以把 `./failure` 的实际终止作为补充 hosted observation，但它**不满足 canonical debugger evidence**；请标为 BLOCKED/PARTIAL。

## 5. Smoke test and cleanup

```bash
./smoke-test.sh
./reset.sh
```

smoke test 检查 architecture/tool availability、compile/link、baseline、`helper` symbol、disassembly、当前 hosted build 的 direct failure class；只有 GDB 可用时才继续三点 trace 与 debugger failure evidence。它不会把缺失 GDB 伪装成 PASS。

## Claim-layer quick reference

| Claim | Layer | Best evidence here |
|---|---|---|
| `helper` 先形成 `a+b`，再加 `item->value` | C/source semantics | source + baseline |
| `add`/`mov` 等 instruction effect | x86-64 ISA | AMD64 manual + disassembly as instance |
| 本次调用的前三个 integer/pointer arguments / return role | System V AMD64 ABI | psABI + GDB observation |
| `local` 的具体 frame offset | compiler/build observation | current disassembly/GDB |
| 无效访问在这里产生 SIGSEGV | hosted Linux observation | actual run/GDB |
