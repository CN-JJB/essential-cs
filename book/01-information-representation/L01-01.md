# L01-01｜信息不是它的表示

## 学习者问题

同一个数值、同一段文本，为什么可以写成十进制、二进制、十六进制或一串 bytes？机器“看到”的到底是什么？

本课是 **EC-CON-003 表示（Representation）** 的 canonical first home。

## 为什么重要

后面的机器指令、文件格式、网络消息、数据库记录都会涉及表示。如果把“信息本身”和“承载信息的具体编码/结构”混为一谈，你会把一个格式的性质误当成信息本身的性质。

## 学习目标

完成本课后，你应能：

- 解释 bit、byte、binary、hex 在本课程里的最小角色；
- 用有限 bit width 推出可区分 pattern 数量；
- 读取一小段 exact bytes，而不是做大量进制换算题；
- 区分 information 与 representation；
- 说明同一信息可以有多种 representation，各有不同成本和规则。

## 前置知识

- L00-01；
- 会整数加减和简单的 2 的幂。

不要求数字电路、布尔代数或信息论。

## Canonical Concept｜EC-CON-003 表示（Representation）

**Canonical definition：**用于承载信息的具体编码或结构。同一信息可以有多种表示，它们可能具有不同的成本和有效性规则。

关键词是“**承载**”：bytes 不会脱离解释规则自动带着意义。

## Mental Model｜一份信息，多种表示

```mermaid
flowchart TB
    INFO[信息：整数 513] --> TEXT[十进制文本表示\n"513"]
    INFO --> FIXED[同一 16-bit pattern\nbinary 00000010 00000001\nhex 0x0201]
    FIXED --> LE[2-byte little-endian\n01 02]
    FIXED --> BE[2-byte big-endian\n02 01]
    LE --> NOTE[解释规则决定 bytes 如何还原为信息]
    BE --> NOTE
```

**图的教学目的：**把 logical information 放在中心，把不同表示画成可替换的外层形式。

`01 02` 和 `02 01` 都可能承载整数 513，但前提是解释者知道对应的 byte order。没有解释规则，“01 02”只是一组 byte values。

## Mechanism 1｜bit、byte 与有限 pattern

在这个课程环境里，我们把：

- **bit** 当作有两个可能状态/符号的表示单位：`0` 或 `1`；
- **byte** 当作 8 bits 的单位；
- `n` bits 可形成 `2^n` 个不同 bit patterns。

因此：

- 1 bit → 2 patterns；
- 8 bits → 256 patterns；
- 16 bits → 65,536 patterns。

这里还没有说这些 patterns “代表哪些数”。那取决于表示规则：unsigned、signed、text encoding 等。

## Mechanism 2｜为什么 hex 适合看 bytes

一个 hexadecimal digit（十六进制数字）恰好对应 4 bits：

```text
0    0000
1    0001
...
f    1111
```

所以一个 8-bit byte 可以紧凑写成两个 hex digits：

```text
0100 0001  →  0x41
```

这就是本课程使用 hex 的主要理由：**它是检查 bytes 的方便记法，不是“机器真正存的是十六进制”。**

## Observe｜检查记录，不做 conversion marathon

```bash
python3 activity.py inspect
```

关注这几行：

```text
field.id offset=4 size=2 bytes=01 02
field.delta offset=6 size=2 bytes=fe ff
field.text_len offset=8 size=2 bytes=04 00
```

此时你只需要能读出：

- `id` 占 2 bytes；
- bytes 用 hex 展示；
- “这两个 bytes 是 id”来自**记录格式中的 field boundary**，不是 bytes 自己携带字段名。

## Build｜手工标注 14-byte payload

把 baseline hex 复制到证据模板：

```text
45 43 53 31 01 02 fe ff 04 00 41 e4 b8 ad
```

按 `inspect` 给出的 offset 用竖线标注：

```text
45 43 53 31 | 01 02 | fe ff | 04 00 | 41 e4 b8 ad
   magic       id      delta   length      text
```

这一步的目标不是背格式，而是训练：“**一个 byte sequence 在某个 representation contract 下才有结构。**”

## Explain｜哪一个是 information，哪一个是 representation？

对 `id=513` 写两句：

- Information：__________
- Representation：__________

然后再举一个不同 representation，例如十进制字符串 `"513"`，说明它与 2-byte integer representation 的大小和解析规则不同。

## Judge｜表示选择必须带约束

在下面约束中，你会倾向哪一种？只做 bounded judgment，不需要普适结论。

**约束 A：**固定 16-bit field，解码器已经约定 byte order。
**约束 B：**人直接阅读/编辑，数值范围不固定在 16 bits。

比较：

- 2-byte integer representation；
- UTF-8 text `"513"`。

至少谈一个 cost 或 validity rule；不要回答“二进制更底层所以永远更好”。

## Common Misconceptions

### “Bits 自己有意义”

没有解释规则，bit pattern 只是 pattern。同一 pattern 可以在不同上下文代表 unsigned integer、signed integer、字符编码的一部分或别的结构。

### “Hex 是机器存储格式”

Hex 是人方便查看 bits/bytes 的记法。

### “二进制表示越低层越真实”

“真实”不是有用的判断标准。不同 representation 服务不同 interface 和约束。

### “学 representation 就是练进制转换速度”

不是。本课只需要足够的 binary/hex reasoning 来检查有限 machine representations。
