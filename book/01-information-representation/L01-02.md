# L01-02｜有限整数：边界先于“溢出故事”

## 学习者问题

为什么一个数学上很普通的整数，在有限宽度的机器表示里会突然“放不下”？负数又怎样进入 bit pattern？

## 为什么重要

机器 representation 是有限的。边界错误常发生在“我以为这个数还能放进去”或“我以为它一定会 wrap”这两种直觉上。

本课只建立**有限整数表示**的准确基础，不把某种硬件 representation 直接当成所有 programming-language arithmetic semantics。

## 学习目标

你将能够：

- 推出 `n`-bit unsigned/signed 的 bounded range；
- 解释 16-bit two's-complement（补码）中正负数的表示边界；
- 用 exact bytes 检查 `-2`；
- 识别最小值、最大值、0、-1 等 boundary cases；
- 明确说出：**representation ≠ programming-language arithmetic semantics**。

## 前置知识

- L01-01；
- 2 的幂与简单二进制/hex 阅读。

## Mental Model｜先问“有多少 pattern”，再问“怎么分配意义”

16 bits 一共有：

```text
2^16 = 65,536 patterns
```

### Unsigned 16-bit

所有 patterns 都分配给非负整数：

```text
0 ... 65,535
```

即：

```text
0 ... 2^16 - 1
```

### Signed 16-bit two's complement

同样是 65,536 patterns，但一部分解释为负数：

```text
-32,768 ... 32,767
```

即：

```text
-2^15 ... 2^15 - 1
```

这里没有“多出一个负数”的神秘规则；只是 65,536 个 patterns 被分配到一个包含负数的连续整数区间。

## Mechanism｜two's complement 的最小必要直觉

对固定 `n` bits，负整数 `x` 的 two's-complement pattern 可以理解为：

```text
2^n + x
```

例如 16-bit 的 `-2`：

```text
2^16 - 2 = 65534 = 0xfffe
```

因此大端阅读时 pattern 是：

```text
11111111 11111110
```

注意：这是**表示规则**。它告诉你 bit pattern 怎样对应 signed value。

## Critical Boundary｜representation ≠ language arithmetic semantics

请把下面这句话作为本课的硬边界：

> **“现代 signed integer 可以使用 two's-complement representation”不等于“所有 programming language 的 signed overflow 都会 wrap”。**

原因是两个问题不同：

1. **Representation question：**某个 representable signed value 对应哪个 bit pattern？
2. **Language-semantics question：**表达式产生超出该类型数学范围的结果时，语言规范规定发生什么？

不同语言、不同类型可能给出不同语义。你必须查对应 language specification / documentation，而不能仅从硬件常见 representation 推导。

一个具体的 specification 例子：C23 已把 two's complement 作为 signed integer representation；但这并不授权你把“signed overflow always wraps”写成 C 的普遍语义。这个 lesson 不教授 C overflow 细节，只用它说明“表示层”和“语言语义层”必须分开。

## Explain｜用两个句子守住层次

完成：

- **Representation claim：**“在本活动的 16-bit two's-complement field 中，`-2` 的 bit pattern 是……。”
- **Semantics boundary：**“如果某编程语言中的 16-bit-like signed operation 计算出 32768，我不能只凭 two's-complement representation 判断结果；我还必须查……。”

## Judge｜哪条证据回答哪条 claim？

Claim A：“C23 的 signed representation 要求是什么？”
Claim B：“本活动 `encode_int16` 对 32768 做什么？”

- WG14 / C specification route；

## Common Misconceptions

### “最高 bit 是 minus sign，所以直接去掉它就行”

这会把 two's complement 误成 sign-magnitude。two's complement 的负数解释是完整的 `n`-bit pattern 规则。

### “two's complement = overflow wrap”

错。representation 与 language arithmetic semantics 是不同层。

### “signed 比 unsigned 少一个 pattern”

两者都有同样数量的 bit patterns；只是 value 分配不同。

### “只测试 0 和 1 就能证明整数处理正确”

边界值更容易暴露 width/range 错误。

## Progressive Stuck Support

先独立回答 Question。只有卡住时，才按顺序展开后面的提示；不要一次打开全部答案。

### Question

为什么 16-bit signed max 是 32767，而不是 65535？

<details>
<summary><strong>Hint 1</strong></summary>

总 pattern 数仍是 65536；signed representation 需要同时覆盖负数。

</details>

<details>
<summary><strong>Hint 2</strong></summary>

two's-complement 的区间是 `-2^(n-1)` 到 `2^(n-1)-1`。

</details>

<details>
<summary><strong>Expected Observation</strong></summary>

活动报告 `int16.range=-32768..32767`；`-2` 的 bit pattern 为 `1111111111111110`，在 big-endian hex 写作 `fffe`，在 fixture 的 little-endian bytes 中是 `fe ff`。

</details>

<details>
<summary><strong>Full Explanation</strong></summary>

固定 16 bits 只能提供 65536 个 patterns。unsigned 把它们映射到 0..65535；two's-complement signed 把它们映射到 -32768..32767。`-2` 对应 pattern `0xfffe`；byte order 再决定这 16 bits 分成两个 bytes 后的排列。任何“超范围算术会怎样”的问题必须另外查看语言语义，不能从该 representation 直接推出。

看过 Full Explanation 后，用 `-32768` 或 `32767` 做一次边界 Transfer。

</details>
