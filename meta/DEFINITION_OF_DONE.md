# Definition of Done

## Core teaching item

A Core Lesson/Module is not complete merely because prose exists. As applicable it must have:

- explicit learning objective;
- prerequisites;
- canonical concepts and sources;
- an accurate mental model;
- mechanism explanation;
- clear distinction between stable principle and implementation/current practice;
- active understanding: predict/observe/explain/judge rather than passive reading only;
- runnable lab or justified reason no lab is appropriate;
- useful visual where a mechanism benefits from one;
- common misconceptions;
- `What You Can Ignore—for Now` where cognitive load needs scoping;
- Exit Criteria;
- consistent terminology/concept IDs;
- competency mapping;
- Mini Cloud App or Beyond-the-Project connection where appropriate;
- provenance/licensing;
- time-sensitivity classification and review date when needed.

## Lab

A REQUIRED lab must be reproducible in the canonical Linux environment and include learning goal, prerequisites, setup, prediction, steps, expected observations, explanation, controlled break/failure where useful, cleanup/reset, exit criteria, provenance/license, and automated smoke test where practical.

## Research Dossier

A dossier is complete when it gives the next designer/writer enough verified evidence to design the module without rediscovering basic sources, and clearly identifies uncertainty/open questions.

## VERIFIED

Before `VERIFIED`, work must pass independent multi-role review for technical accuracy, pedagogy, lab quality, and curriculum integration. Author self-approval is not sufficient.

## v1.0

v1.0 means teachable, not merely written. See `RELEASE_AND_MAINTENANCE_POLICY.md`.
