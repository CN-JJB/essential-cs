# Local Agent Task Prompt Specification

Every formal Local Agent Task Prompt generated by the Web Lead should be self-contained enough to execute against the repository without copying chat history.

## Required fields

- Task ID / GitHub Issue
- Role
- Goal
- Why this task exists
- Current project phase
- Base branch and work branch
- Repository state / commit checked when practical
- Dependencies
- Parallel-safety statement
- Work Claim:
  - files
  - canonical concepts
  - module/project areas
- Read first
- Relevant Decisions/Policies
- Allowed edits
- Forbidden edits
- Required investigation/work
- Deliverables
- Verification
- Relevant Definition of Done
- Open questions/known risks
- PR/commit expectations
- Completion Report schema

## Rules

- Do not paste the whole project history into a Task Prompt; point the agent to canonical repository artifacts.
- A Task Prompt cannot override Curriculum Invariants.
- If repository state materially changed since dispatch, the agent should flag staleness rather than guessing.
- State whether multiple dispatched tasks can run in parallel and any review/merge ordering.
