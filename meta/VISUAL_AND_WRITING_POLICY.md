# Visual & Writing Policy

## Language and tone

Canonical teaching language is Chinese. On first important use, include the English technical term. Maintain one primary translation per canonical concept.

Write for capable adult learners: accessible, precise, and non-patronizing.

Use:

`problem → intuition → formal term → mechanism → limits of model`

Analogies must state where they break when the boundary matters.

## Lesson structure

Default loop:

`Question → Mental Model → Mechanism → Observe → Build → Break → Explain → Judge → Project`

Also include, as appropriate:

- prerequisites;
- why this matters;
- checkpoints;
- Common Misconceptions;
- What You Can Ignore—for Now;
- Exit Criteria;
- progressive stuck support.

## Canonical explanation

Teach definitions/core mechanisms in one primary location. Later locations should recap briefly and deepen through application/context rather than copying whole explanations.

## Visual-first, not decorative-first

Use visuals when they materially improve a mental model:

- system maps;
- mechanism diagrams;
- timelines;
- state transitions;
- request/data paths;
- memory layouts;
- transaction interleavings;
- failure propagation;
- architecture comparison.

For abstract mechanisms, prefer original/redrawn visuals aligned to the course. Keep editable diagram source when practical.

External visuals require source/license/attribution.

Local agents may add a `VISUAL_REQUEST` describing purpose, required mental model, and must-show elements. The Web Lead owns final visual quality and should directly create/revise final images during review.
