# Curriculum Blueprint v0.1

## Purpose

Blueprint v0.1 defines **what Essential CS will teach, why, in what dependency order, through which capabilities/projects/labs, and under which production/review rules** before large-scale lesson writing.

## Exit criteria

Blueprint v0.1 is complete when the repository contains coherent, reviewable versions of:

- Course Charter
- Curriculum Invariants
- Learner Profile
- Learning Outcomes
- Big Ideas
- Core Stage / Module Map
- Lesson Map
- Dependency Graph
- Competency Matrix
- Mini Cloud App Evolution Map
- Lab Map
- Source Expedition Map
- Modern Technology Case Map
- Assessment Architecture
- Bridge
- Deep Dive / Extension boundaries
- Repo Architecture
- Research / Source / Provenance Policy
- Lab Design Policy
- Writing / Visual / Terminology policies
- Concept Registry policy and initial structure
- Living Curriculum / Maintenance Policy
- Definition of Done
- Review Policy
- Multi-Agent Collaboration Protocol
- Work Session / Prompt Protocol
- Progress / Decision / Handoff system
- v1.0 Release Criteria
- External Curriculum Audit v0.1
- explicitly tracked Open Questions

## Three highest-priority maps

1. Curriculum / Lesson Map
2. Dependency Graph
3. Mini Cloud App Evolution Map

## Blueprint is not

- a request to generate all lessons;
- a fixed time budget;
- a product/framework syllabus;
- a replacement for module-level Research Dossiers.

## Construction after Blueprint

Prefer stage-by-stage vertical slices:

`Research → Design → Lesson → Lab → Project → Verification → Learner Validation`

The first full pilot should use an early Foundations / System Mechanics slice rather than the most complex distributed-systems material.
